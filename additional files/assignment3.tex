\section{MVP v1 Access Instructions}

The MVP v1 architecture has migrated from the legacy Python \texttt{http.server} dashboard to a \textbf{FastAPI + Docker} stack. Two access methods are available.

\subsection{Method A — Docker (recommended)}

\begin{enumerate}[leftmargin=*]
    \item Clone the repository at the submission commit:
\begin{verbatim}
git clone https://github.com/Fedos113/SWP_TickFrame_28_team.git
cd SWP_TickFrame_28_team
git checkout 86e19a02e9f8c0373b8a874a2714963bdbc6e48f
\end{verbatim}

    \item Copy the environment template:
\begin{verbatim}
cp .env.example .env
\end{verbatim}

    \item Build and run with Docker Compose:
\begin{verbatim}
docker compose up --build
\end{verbatim}

    \item Open \texttt{http://localhost:8000} in a browser to access the interactive chart dashboard.
\end{enumerate}

\subsection{Method B — Local development (no Docker)}

\begin{enumerate}[leftmargin=*]
    \item Clone and checkout as above.
    \item Create a virtual environment and install dependencies:
\begin{verbatim}
python -m venv .venv
.venv\Scripts\Activate.ps1   # Windows
# source .venv/bin/activate  # Linux/macOS
pip install -r requirements.txt
\end{verbatim}

    \item Start the FastAPI server:
\begin{verbatim}
uvicorn tickframe.backend.main:app --host 0.0.0.0 --port 8000
\end{verbatim}

    \item Open \texttt{http://localhost:8000} in a browser.
\end{enumerate}

\subsection{Verification}

Once the server is running, confirm the following endpoints respond:

\begin{itemize}
    \item \texttt{GET /api/health} — returns \texttt{\{"status": "ok"\}}
    \item \texttt{GET /api/coins} — returns the list of available trading pairs with live prices
    \item \texttt{GET /api/coins/BTCUSDT/candles?interval=5m\&limit=200} — returns OHLCV candle data
    \item \texttt{WS /ws/candles/BTCUSDT?interval=5m} — real-time candle stream (connect via WebSocket client)
\end{itemize}

\subsection{Customer feedback summary}
The customer reviewed the Figma dashboard design and the current MVP v1 implementation. Key feedback points:

\begin{itemize}
    \item \textbf{Indicators required:} Fear \& Greed Index, volume chart, and RSI indicator must be added to the dashboard.
    \item \textbf{Drawing tools:} A drawing toolbar (figures, Fibonacci, brush) is needed on the chart.
    \item \textbf{Theme support:} Both light and dark themes should be supported.
    \item \textbf{Customization:} Candle color customization was requested.
    \item \textbf{Authentication:} Confirmed not required for MVP.
    \item \textbf{Pattern visualization:} Additional Figma screens are needed to demonstrate how patterns, metrics, and multiple simultaneous patterns will be displayed.
    \item \textbf{Pattern list:} A dedicated pattern panel (similar to the coin list) was suggested — selecting a pattern should highlight its location on the chart.
    \item \textbf{Continuous scanning:} ML should scan the entire chart using rolling windows, not just the latest 50 candles.
    \item \textbf{Charting library:} TradingView's capabilities must be researched; alternatives should be evaluated if TradingView cannot satisfy all requirements.
    \item \textbf{Task tracking:} GitHub Projects was recommended for Kanban-style task management.
\end{itemize}

\subsection{Approvals and requested changes}

\textbf{Approved for MVP:}
\begin{itemize}
    \item Fear \& Greed Index
    \item Volume chart
    \item RSI indicator
    \item Drawing tools
    \item Theme switching (light/dark)
    \item Exclusion of authentication/registration
\end{itemize}

\textbf{Requested changes / follow-up:}
\begin{itemize}
    \item Research TradingView capabilities and limitations before adopting it as the primary charting solution.
    \item Evaluate alternative charting technologies if TradingView cannot satisfy all requirements.
    \item Extend Figma with pattern visualization and metric placement examples.
    \item Define final pattern representation and behavior for multiple simultaneous patterns.
    \item Continue reviewing Figma updates asynchronously without scheduling another meeting.
\end{itemize}

\subsection{Resulting Product Backlog updates}
The following PBIs were added or re-prioritised based on customer feedback:

\begin{itemize}
    \item \textbf{US-10 — Volume chart below the main chart} — promoted to Sprint 3 (was backlog).
    \item \textbf{US-11 — RSI chart below the main chart} — promoted to Sprint 3 (was backlog).
    \item \textbf{US-13 — Toggle between day theme and night theme} — promoted to Sprint 3 (was backlog).
    \item \textbf{Crypto Fear \& Greed Index} — new PBI added to the product backlog.
    \item \textbf{Drawing toolbar (US-08)} — remained in backlog, priority confirmed as Should Have.
    \item \textbf{Authentication/registration} — formally removed from MVP scope.
\end{itemize}
